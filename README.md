# Аналитика рекламы Wildberries

Свой сервис аналитики рекламных кампаний WB: собирает статистику к вам в базу,
показывает динамику и **сам находит проблемные кампании с объяснением, что делать**.

Не «ещё одна таблица с цифрами»: сервис отвечает на вопрос «куда смотреть
сегодня». Каждая проблема — с цифрами, причиной и списком действий.

```
Что сделать сегодня
 1  Аукцион · Худи оверсайз — ДРР 42,2% при цели 15%
    Причина — подорожавший клик: аукцион разогрелся. Снижайте ставку осознанно
    и следите, сколько объёма теряете.
 2  Авто · Свеча ароматическая — Расход без единого заказа
    Остановите кампанию сегодня — каждый следующий день это чистый минус.
```

---

## Быстрый старт

Нужен только **Python 3.10 или новее**. Ничего устанавливать не надо —
сервис работает на стандартной библиотеке.

```bash
python3 run.py demo     # заполнить базу демо-данными
python3 run.py serve    # открыть дашборд в браузере
```

Дашборд откроется на `http://127.0.0.1:8000`. Демо-кабинет специально собран
из «больных» кампаний — так видно, как работает диагностика.

> **Windows:** вместо `python3` пишите `python`.
> Проверить версию: `python --version`.

## Подключить свой кабинет

**1. Получите токен.**
Кабинет WB → **Настройки** → **Доступ к API** → **Создать новый токен**.
Отметьте категории **«Продвижение»** (обязательно) и **«Статистика»**.
Токен показывается один раз — скопируйте его сразу.

**2. Впишите токен в файл настроек.**

```bash
cp .env.example .env      # Windows: copy .env.example .env
```

Откройте `.env` любым текстовым редактором и вставьте токен:

```
WB_API_TOKEN=eyJhbGciOiJFUzI1NiIsImtpZCI6...
```

Файл `.env` не попадает в git — токен останется только у вас на компьютере.

**3. Проверьте, что всё работает.**

```bash
python3 run.py check
```

Должно ответить балансом кабинета и числом кампаний.

**4. Соберите данные и откройте дашборд.**

```bash
python3 run.py collect --days 30
python3 run.py serve
```

> Первый сбор идёт медленно: WB отдаёт рекламную статистику **раз в минуту**.
> Сервис сам выдерживает паузы — просто дайте ему доработать.
> Если кампаний больше сотни, заложите несколько минут.

## Что показывает дашборд

**Что сделать сегодня** — пять самых дорогих проблем периода, сверху вниз.

**Показатели за период** со сравнением с предыдущим таким же периодом:
расход, выручка с рекламы, ДРР, заказы, цена заказа, ROAS, а также
«уходит мимо цели» — сколько денег вы переплачиваете сверх целевого ДРР.

**Графики по дням** — расход и выручка на одной шкале в рублях, и отдельно
ДРР с линией вашей цели.

**Кампании** — отсортированы по срочности: сначала те, где на кону больше денег.
Прямо в строке видно, что не так. Нажмите на кампанию — откроются
разбор с рекомендациями, графики динамики и **разбивка по артикулам внутри**
(обычно 20% товаров съедают половину бюджета — здесь видно, каких).

Ссылка вида `http://127.0.0.1:8000/?open=21400105` сразу раскрывает нужную
кампанию — удобно отправить коллеге.

Кнопка **«Выгрузить в CSV»** отдаёт сводку для Excel.

## Какие проблемы находит

| Что ловим | Когда срабатывает | Куда ведёт |
|---|---|---|
| 🔴 Расход без единого заказа | Потрачено больше порога, заказов ноль | Остановить, проверить остатки и цену |
| 🔴 Активна, но без показов | Статус «идут показы», 4+ дня тишины | Баланс кабинета, дневной бюджет, остатки, ставка |
| 🔴 ДРР сильно выше цели | ДРР ≥ цель × 1,5 | Ставка, отключение худших артикулов |
| 🟡 ДРР выше цели | ДРР между целью и целью × 1,5 | Снизить ставку на 10–15% |
| 🟡 ДРР ухудшается | Рост ДРР более 20% к прошлому периоду | Найти причину: клик или конверсия |
| 🟡 Клик подорожал | CPC +30% к прошлому периоду | Разогретый аукцион, ставки конкурентов |
| 🟡 CTR упал | CTR −30% к прошлому периоду | Главное фото, цена в выдаче, отзывы |
| 🟡 Низкий CTR | CTR ниже 1% | Фото, релевантность запросов |
| 🟡 Клики не доходят до корзины | Конверсия клик → корзина ниже 5% | Проблема карточки, не ставки |
| 🟡 Корзина не превращается в заказ | Конверсия корзина → заказ ниже 20% | Цена, сроки доставки, отзывы |
| 🟡 Показы обвалились | Показы −50% к прошлому периоду | Баланс, бюджет, ставка, остатки |
| 🟡 Расход вырос, заказы нет | Расход +40% при том же числе заказов | Вернуть прежние настройки |
| 🟡 Заказ подорожал | CPO +30% к прошлому периоду | Клик или конверсия |
| 🚀 Упирается в дневной бюджет | Лимит выбирается, ДРР в цели | Поднять бюджет на 30–50% |
| 🚀 Работает лучше цели | ДРР ниже цели × 0,6 | Масштабировать, проверив остатки |
| ⚪️ Почти не откручивается | Активна, но расход меньше 50 ₽ | Поднять ставку или закрыть |

**Причина важнее следствия.** Высокий ДРР почти всегда — следствие. Если сервис
нашёл настоящую причину (подорожал клик, упал CTR, не доходят до корзины),
рекомендация к ДРР ведёт именно к ней, а не советует «снизьте ставку» там,
где ставка ни при чём.

## Настройка порогов

**Целевой ДРР** меняется прямо в дашборде — поле «Цель ДРР» в шапке.
Значение сохраняется в базу и переживает перезапуск.

Остальные пороги — в файле `.env`:

```
WBADS_TARGET_DRR=15        # целевой ДРР, %
WBADS_MIN_SPEND=300        # ниже этого расхода кампанию не разбираем
WBADS_SPEND_NO_ORDERS=1500 # расход без заказов, после которого это критично
WBADS_PORT=8000            # порт дашборда
```

Тонкая настройка (пороги CTR, конверсий, скорости роста CPC) — в классе
`Thresholds` в файле `wbads/config.py`. Каждый порог прокомментирован.

Какую цель ДРР ставить: **10%** — жёсткий контроль маржи, **15%** — обычный
ориентир, **20–25%** — когда важнее оборот или вывод новинок.

## Сбор по расписанию

Чтобы история копилась сама, запускайте сбор раз в сутки.

**macOS / Linux** — `crontab -e`, добавить строку (сбор в 7 утра):

```
0 7 * * * cd /путь/к/проекту && /usr/bin/python3 run.py collect --days 7 >> collect.log 2>&1
```

**Windows** — Планировщик заданий → Создать простую задачу → Ежедневно →
Запуск программы: `python`, аргументы: `run.py collect --days 7`,
рабочая папка: папка проекта.

Собирать каждый день по 7 дней достаточно: WB иногда уточняет цифры задним
числом, и повторный сбор их обновит. Дублей не будет — данные обновляются
по ключу «кампания + день».

## Как устроен проект

```
[Сбор данных]  →  [Хранилище]  →  [Бэкенд-API]  →  [Веб-дашборд]
 wb_client.py      SQLite         api.py           web/
 collector.py      db.py          analytics.py     (графики — инлайновый SVG)
                                  metrics.py
                                  rules.py
```

| Файл | За что отвечает |
|---|---|
| `wbads/wb_client.py` | Запросы к API продвижения WB, лимиты, повторы при сбоях |
| `wbads/collector.py` | Сбор данных в базу, накопление истории по дням |
| `wbads/db.py` | Схема SQLite и запросы |
| `wbads/metrics.py` | Формулы: CTR, CPC, CPO, ДРР, ROAS, тренды |
| `wbads/rules.py` | **Правила диагностики и тексты рекомендаций** |
| `wbads/analytics.py` | Сборка отчёта из базы, метрик и правил |
| `wbads/api.py` | HTTP-эндпоинты и локальный сервер |
| `wbads/web/` | Дашборд: разметка, стили, графики |
| `wbads/demo.py` | Генератор демо-кабинета |

Слои разделены намеренно: можно заменить SQLite на Postgres или HTTP-сервер
на FastAPI, не трогая аналитику.

### Добавить своё правило

Правило — это функция, которая смотрит на кампанию и либо молчит, либо
возвращает находку. В `wbads/rules.py`:

```python
@rule
def my_check(ctx: Context) -> Finding | None:
    if ctx.cur["cpc"] < 20:
        return None
    return Finding(
        code="cpc_too_high",
        severity=WARNING,
        title=f"Клик дороже 20 ₽ — {rub(ctx.cur['cpc'])}",
        why="Такая цена клика окупается только на дорогом товаре.",
        actions=["Проверьте, попадаете ли вы в целевые запросы."],
    )
```

Внутри `ctx` есть всё: `ctx.cur` — показатели за период, `ctx.prev` —
за предыдущий, `ctx.cmp` — изменения, `ctx.series` — ряд по дням.

## Если что-то пошло не так

**«Токен не принят (401)»** — токен скопирован не полностью или выпущен
в другом кабинете. Создайте новый в разделе «Доступ к API».

**«Доступ запрещён (403)»** — у токена нет категории «Продвижение».
Категории задаются при создании токена и не меняются потом — нужен новый.

**«Слишком часто (429)»** — сработал лимит WB. Сервис сам подождёт и повторит;
если повторяется — уменьшите `--days`.

**Порт занят** — `python3 run.py serve --port 8080`.

**Данных нет за нужные даты** — WB отдаёт рекламную статистику ограниченной
глубины. Чем раньше начнёте собирать, тем длиннее ваша история; в кабинете
её потом взять будет негде.

## Куда развивать

- **Себестоимость и настоящая маржа.** Сейчас ДРР считается от выручки с рекламы.
  Добавьте таблицу себестоимости — и сервис покажет прибыль после рекламы (МП-3).
- **Остатки.** Половина рекламных проблем — это отсутствие товара на складах.
  Сбор остатков рядом с рекламой даст правило «рекламируем то, чего нет».
- **Ставки и ключевые запросы** — отдельные методы API WB, ложатся тем же слоем сбора.
- **Автоматические действия** — снижение ставки по правилу через API.
- **Уведомления** — отправлять «что сделать сегодня» в Telegram по утрам.

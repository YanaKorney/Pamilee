# Аналитика рекламы Wildberries

Свой сервис аналитики рекламных кампаний WB: собирает статистику к вам в базу,
показывает динамику и **сам находит проблемные кампании с объяснением, что делать**.

Не «ещё одна таблица с цифрами»: сервис отвечает на вопрос «куда смотреть
сегодня». Каждая проблема — с цифрами, причиной и списком действий.

```
Что сделать сегодня
 1  Аукцион · Худи оверсайз — ДРР 42,2% при цели 15%
    Причина — подорожавший клик: аукцион разогрелся. Снижайте ставку осознанно
    и следите, сколько объёма теряете.
 2  Авто · Свеча ароматическая — Расход без единого заказа
    Остановите кампанию сегодня — каждый следующий день это чистый минус.
```

## Быстрый старт

Нужен только **Python 3.10 или новее** — больше ничего устанавливать не надо.

**Самый простой способ — двойной клик:**

| Ваш компьютер | Файл |
|---|---|
| Windows | `START-Windows.bat` |
| Mac | `START-Mac.command` |

> Имена латиницей намеренно: русские названия ломаются при распаковке архива
> в Windows — Проводник читает их в старой кодировке и показывает кашу.

Откроется окно, которое проведёт вас по шагам: спросит токен, заберёт данные
и откроет дашборд в браузере. На Mac при первом запуске система может сказать
«неопознанный разработчик» — тогда правый клик по файлу → «Открыть».

**Через командную строку — то же самое:**

```bash
python3 run.py
```

Без аргументов запускается мастер. Он сам поймёт, что уже настроено,
а что нет, и спросит только про недостающее.

Если токена пока нет, мастер предложит показать демо-кабинет: он собран
из намеренно «больных» кампаний, так что сразу видно, как работает диагностика.

> **Windows:** вместо `python3` пишите `python`.

## Подключить свой кабинет

**1. Получите токен.**
Кабинет WB → **Настройки** → **Доступ к API** → **Создать новый токен**.

Отметьте **две категории — «Продвижение» и «Статистика»**:

- **Продвижение** — кампании и статистика рекламы. Без неё сервис не работает.
- **Статистика** — заказы кабинета. Нужна для **общего ДРР** (реклама против
  всего оборота, а не только рекламных заказов). Без неё сервис считает
  рекламный ДРР и молчит про общий.

Категории задаются при создании токена и потом не меняются, поэтому отметьте
обе сразу — иначе для общего ДРР придётся выпускать новый токен.

| Настройка при создании | Что ставить |
|---|---|
| Категории | **Продвижение** + **Статистика** |
| Только на чтение | **Да** — сервис ничего не меняет в кабинете |
| Тестовый контур | **Нет** — иначе придут не ваши данные |

Токен показывается **один раз** — скопируйте его сразу. Категории и режим
задаются при создании и потом не меняются: чтобы что-то поправить, выпускают
новый токен.

> Если с галочкой «Только на чтение» сбор отвечает ошибкой 403 — выпустите
> токен без неё. Статистика запрашивается методом POST, и WB в отдельных
> случаях считает такой запрос изменяющим.

**Что дают категории WB (на будущее):**

| Категория | Что открывает | Нужна сейчас |
|---|---|---|
| **Продвижение** | Кампании, ставки, статистика рекламы, баланс кабинета | **Да** |
| **Статистика** | Заказы кабинета, продажи, остатки FBO | **Да** — для общего ДРР |
| Финансы | Отчёт о реализации, удержания | Нет — понадобится для маржи МП-3 |
| Контент | Карточки товаров, фото, описания | Нет — названия артикулов приходят вместе с рекламной статистикой |

**2. Отдайте токен сервису.**

```bash
python3 run.py setup
```

Команда спросит токен и сохранит его сама — редактировать файлы не нужно.
Символы при вводе не отображаются, это нормально: просто вставьте и нажмите Enter.

Токен ляжет в файл `.env`, который git игнорирует. Он останется только
у вас на компьютере.

> **Не вписывайте токен в `.env.example`.** Это шаблон, он лежит в репозитории
> и уедет на GitHub. Сервис его оттуда не читает, так что токен ещё и не
> заработает. Если уже вписали — `python3 run.py setup` сам перенесёт его
> в `.env` и очистит шаблон.

**3. Заберите данные и откройте дашборд.**

```bash
python3 run.py collect --days 30
python3 run.py serve
```

Или просто `python3 run.py` — мастер сделает оба шага сам.

> Первый сбор идёт медленно: WB отдаёт рекламную статистику **раз в минуту**.
> Сервис сам выдерживает паузы — просто дайте ему доработать.
> Если кампаний больше сотни, заложите несколько минут.

## Что показывает дашборд

**Что сделать сегодня** — пять самых дорогих проблем периода, сверху вниз.

**Показатели за период** со сравнением с предыдущим таким же периодом:
расход, выручка с рекламы, ДРР, заказы, цена заказа, ROAS, а также
«уходит мимо цели» — сколько денег вы переплачиваете сверх целевого ДРР.

**Два ДРР рядом.** Это главное отличие от рекламного отчёта в кабинете:

| Показатель | Знаменатель | О чём говорит |
|---|---|---|
| **ДРР рекламный** | Заказы, которые WB атрибутировал рекламе | Эффективность самой открутки |
| **ДРР общий** | Все заказы артикула — реклама и органика | Настоящая нагрузка рекламы на оборот |

Реклама поднимает и органические продажи, поэтому рекламный ДРР почти всегда
выглядит хуже общего. На демо-данных это видно сразу: у кампании «Худи оверсайз»
рекламный ДРР 42%, а общий — 9%. По рекламному отчёту её хочется отключить,
и это была бы дорогая ошибка: 78% оборота этих артикулов приходит без клика
по рекламе, но перестанет приходить вместе с ней.

Сервис ловит такие случаи отдельным правилом и прямо говорит: **не режьте эту
кампанию по рекламному ДРР**.

**Воронка за период** — вся цепочка целиком, с конверсией на каждом шаге
и с тем, что было в прошлом периоде:

```
Показы → CTR → Клики → CR в корзину → В корзине → CR в заказ → Заказы
```

Плюс сквозная конверсия клик → заказ, конверсия показ → заказ и средний чек.
Отдельной строкой — сколько кампаний не дотягивает до порога на каждом шаге:
средняя по кабинету может выглядеть нормально, пока отдельные кампании валятся.

**Графики по дням** — конверсии (по отдельному графику на каждую, потому что
CTR около 2% и конверсия в заказ около 30% на одной шкале нечитаемы), расход
и выручка на одной шкале в рублях, и ДРР с линией вашей цели.

**Кампании** — таблица, отсортированная по срочности: сначала те, где на кону
больше денег. В строке сразу видно, что не так, и вся воронка кампании —
показы, CTR, клики, конверсия в корзину, конверсия в заказ, заказы, расход,
выручка, ДРР — с изменением к прошлому периоду под каждым числом.
Конверсия ниже вашего порога подсвечивается красным, вдвое выше порога —
зелёным. Нажмите на кампанию — откроются разбор с рекомендациями, воронка
кампании, шесть графиков динамики и **разбивка по артикулам внутри**
(обычно 20% товаров съедают половину бюджета — здесь видно, каких, и по
какому шагу воронки они проваливаются).

Ссылка вида `http://127.0.0.1:8000/?open=21400105` сразу раскрывает нужную
кампанию — удобно отправить коллеге.

Кнопка **«Выгрузить в CSV»** отдаёт сводку для Excel.

## Какие проблемы находит

| Что ловим | Когда срабатывает | Куда ведёт |
|---|---|---|
| 🔴 Расход без единого заказа | Потрачено больше порога, заказов ноль | Остановить, проверить остатки и цену |
| 🔴 Активна, но без показов | Статус «идут показы», 4+ дня тишины | Баланс кабинета, дневной бюджет, остатки, ставка |
| 🔴 ДРР сильно выше цели | ДРР ≥ цель × 1,5 | Ставка, отключение худших артикулов |
| 🟡 ДРР выше цели | ДРР между целью и целью × 1,5 | Снизить ставку на 10–15% |
| 🟡 ДРР ухудшается | Рост ДРР более 20% к прошлому периоду | Найти причину: клик или конверсия |
| 🟡 Клик подорожал | CPC +30% к прошлому периоду | Разогретый аукцион, ставки конкурентов |
| 🟡 CTR упал | CTR −30% к прошлому периоду | Главное фото, цена в выдаче, отзывы |
| 🟡 Низкий CTR | CTR ниже 1% | Фото, релевантность запросов |
| 🟡 Клики не доходят до корзины | Конверсия клик → корзина ниже 5% | Проблема карточки, не ставки |
| 🟡 Корзина не превращается в заказ | Конверсия корзина → заказ ниже 20% | Цена, сроки доставки, отзывы |
| 🟡 Показы обвалились | Показы −50% к прошлому периоду | Баланс, бюджет, ставка, остатки |
| 🟡 Расход вырос, заказы нет | Расход +40% при том же числе заказов | Вернуть прежние настройки |
| 🟡 Заказ подорожал | CPO +30% к прошлому периоду | Клик или конверсия |
| 🚀 Упирается в дневной бюджет | Лимит выбирается, ДРР в цели | Поднять бюджет на 30–50% |
| 🚀 Работает лучше цели | ДРР ниже цели × 0,6 | Масштабировать, проверив остатки |
| ⚪️ Почти не откручивается | Активна, но расход меньше 50 ₽ | Поднять ставку или закрыть |

**Причина важнее следствия.** Высокий ДРР почти всегда — следствие. Если сервис
нашёл настоящую причину (подорожал клик, упал CTR, не доходят до корзины),
рекомендация к ДРР ведёт именно к ней, а не советует «снизьте ставку» там,
где ставка ни при чём.

## Как считается общий ДРР

```
ДРР общий (кабинет)  = весь расход ÷ сумма всех заказов кабинета
ДРР общий (артикул)  = расход по артикулу ÷ сумма всех заказов артикула
ДРР общий (кампания) = расход кампании ÷ доля оборота её артикулов
```

**Про долю оборота кампании.** Один артикул часто крутится сразу в нескольких
кампаниях. Если каждой отдать весь его оборот, сумма по кампаниям окажется
больше кабинета, а общий ДРР — занижен. Поэтому оборот артикула делится между
кампаниями пропорционально тому, сколько каждая на него потратила.

**Что учтено:**

- **Отменённые заказы не считаются.** Заказы хранятся построчно, по `srid`,
  поэтому отмена, приехавшая на следующий день, исправляет уже собранный день.
  С агрегатами это было бы невозможно.
- **Какая цена берётся.** По умолчанию `price_with_disc` — сумма после вашей
  скидки, сопоставимая с рекламным отчётом. Переключается в `.env`:

```
WBADS_ORDER_PRICE=price_with_disc   # после скидки продавца (по умолчанию)
WBADS_ORDER_PRICE=finished_price    # что заплатил покупатель, с учётом СПП
WBADS_ORDER_PRICE=total_price       # до скидок
```

- **Это заказы, а не выкупы.** Часть заказов не выкупят, поэтому реальная
  отдача будет ниже. Выкупы приходят с лагом в 2–3 недели — их можно добавить
  тем же слоем сбора, метод `/api/v1/supplier/sales`.

## Настройка порогов

**Целевой ДРР** меняется прямо в дашборде — поле «Цель ДРР» в шапке.
Значение сохраняется в базу и переживает перезапуск.

Остальные пороги — в файле `.env`:

```
WBADS_TARGET_DRR=15        # целевой ДРР, %
WBADS_MIN_SPEND=300        # ниже этого расхода кампанию не разбираем
WBADS_SPEND_NO_ORDERS=1500 # расход без заказов, после которого это критично
WBADS_PORT=8000            # порт дашборда
```

Пороги воронки задаются там же, в классе `Thresholds` (`wbads/config.py`) —
именно по ним конверсия красится красным и считается проблемной:

| Показатель | Как считается | Порог по умолчанию |
|---|---|---|
| CTR | клики ÷ показы | 1% |
| CR в корзину | в корзину ÷ клики | 5% |
| CR в заказ | заказы ÷ в корзину | 20% |
| Сквозная CR | заказы ÷ клики | — (справочно) |

Пороги — ориентир, а не истина: в разных категориях нормы отличаются в разы.
Посмотрите свои цифры за спокойный месяц и поставьте пороги чуть ниже
привычного уровня — тогда сервис будет реагировать на реальные просадки,
а не на фон.

Какую цель ДРР ставить: **10%** — жёсткий контроль маржи, **15%** — обычный
ориентир, **20–25%** — когда важнее оборот или вывод новинок.

## Сбор по расписанию

Чтобы история копилась сама, запускайте сбор раз в сутки.

**macOS / Linux** — `crontab -e`, добавить строку (сбор в 7 утра):

```
0 7 * * * cd /путь/к/проекту && /usr/bin/python3 run.py collect --days 7 >> collect.log 2>&1
```

**Windows** — Планировщик заданий → Создать простую задачу → Ежедневно →
Запуск программы: `python`, аргументы: `run.py collect --days 7`,
рабочая папка: папка проекта.

Собирать каждый день по 7 дней достаточно: WB иногда уточняет цифры задним
числом, и повторный сбор их обновит. Дублей не будет — данные обновляются
по ключу «кампания + день».

## Как устроен проект

```
[Сбор данных]  →  [Хранилище]  →  [Бэкенд-API]  →  [Веб-дашборд]
 wb_client.py      SQLite         api.py           web/
 collector.py      db.py          analytics.py     (графики — инлайновый SVG)
                                  metrics.py
                                  rules.py
```

| Файл | За что отвечает |
|---|---|
| `wbads/wb_client.py` | Запросы к API WB: продвижение и статистика, лимиты, повторы |
| `wbads/collector.py` | Сбор данных в базу, накопление истории по дням |
| `wbads/db.py` | Схема SQLite и запросы, включая построчное хранение заказов |
| `wbads/metrics.py` | Формулы: CTR, CPC, CPO, ДРР, ROAS, тренды |
| `wbads/rules.py` | **Правила диагностики и тексты рекомендаций** |
| `wbads/analytics.py` | Сборка отчёта из базы, метрик и правил |
| `wbads/api.py` | HTTP-эндпоинты и локальный сервер |
| `wbads/web/` | Дашборд: разметка, стили, графики |
| `wbads/demo.py` | Генератор демо-кабинета |

Слои разделены намеренно: можно заменить SQLite на Postgres или HTTP-сервер
на FastAPI, не трогая аналитику.

### Добавить своё правило

Правило — это функция, которая смотрит на кампанию и либо молчит, либо
возвращает находку. В `wbads/rules.py`:

```python
@rule
def my_check(ctx: Context) -> Finding | None:
    if ctx.cur["cpc"] < 20:
        return None
    return Finding(
        code="cpc_too_high",
        severity=WARNING,
        title=f"Клик дороже 20 ₽ — {rub(ctx.cur['cpc'])}",
        why="Такая цена клика окупается только на дорогом товаре.",
        actions=["Проверьте, попадаете ли вы в целевые запросы."],
    )
```

Внутри `ctx` есть всё: `ctx.cur` — показатели за период, `ctx.prev` —
за предыдущий, `ctx.cmp` — изменения, `ctx.series` — ряд по дням.

## Если что-то пошло не так

**«Токен не принят (401)»** — токен скопирован не полностью или выпущен
в другом кабинете. Создайте новый в разделе «Доступ к API».

**«Доступ запрещён (403)»** — у токена нет категории «Продвижение», либо он
выпущен в режиме «Только на чтение», а WB счёл запрос статистики изменяющим.
Категории и режим при создании токена фиксируются и потом не меняются —
выпустите новый.

**«Токен не принят (401)» на токене, который раньше работал** — у токенов WB
есть срок действия. Выпустите новый в том же разделе и замените строку в `.env`.

**«Слишком часто (429)»** — сработал лимит WB. Сервис сам подождёт и повторит;
если повторяется — уменьшите `--days`.

**Порт занят** — `python3 run.py serve --port 8080`.

**Данных нет за нужные даты** — WB отдаёт рекламную статистику ограниченной
глубины. Чем раньше начнёте собирать, тем длиннее ваша история; в кабинете
её потом взять будет негде.

## Куда развивать

- **Выкупы вместо заказов.** Метод `/api/v1/supplier/sales`, та же категория
  токена. Даст ДРР от фактически выкупленного — самый честный, но с лагом.
